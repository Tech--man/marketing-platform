核心链路

券、优惠、秒杀：三条链路各自解决一个具体问题

削峰要的是「早拒优于慢扛」，计算要的是「再快也不能挡住结算」，抢购要的是 「热点不能压垮单 key」。三条链路的取舍不一样，实现方式也就不一样。

  1. 1POST /api/coupon/grant，客户端带 requestId 幂等键
  2. 2网关限流 → 风控扩展点（占位）→ 模板校验 → IdempotentExecutor 抢占
  3. 3Redis + Lua 原子预扣库存，含单人限领
  4. 4写本地消息表 + 投 MQ，立刻返回 ACCEPTED
  5. 5客户端轮询 GET /grant/result/{requestId}
  6. 6消费端幂等落库（user_coupon.request_id 唯一索引兜底）→ confirm 消息

三层幂等，任何一层单独坏掉都不重复发券

idempotent_record 状态机（首执 / 回放 / PROCESSING 拒重入 / FAILED 可重抢）、local_message.biz_key 唯一、业务表唯一索引。

重启与抖动都自愈

LocalMessageRetryer 按退避重投未确认消息；StockWarmUpRunner 启动时按 DB 已发量重算 Redis 库存，而不是把 Redis 当账本。

洪流被拒掉，不是被排队淹掉

LITE 超阈值爆发实测（400 条 / 并发 100）：327 受理 + 73 个 HTTP 429，受理吞吐稳定 ≈104 msg/s——正好等于排空能力。

  1. 1购物车进来，读 volatile 本地快照（位图倒排索引）
  2. 2候选剪枝：标签 OR 位图
  3. 3逐条精确匹配：活动 / 用户标签 / 商品范围 / 门槛
  4. 4互斥组最优组合：≤2 万组合精确枚举，超限转贪心
  5. 5按比例分摊（DOWN）+ 尾差归范围内末项 + 行级剩余额度 cap
  6. 6专用线程池 orTimeout(50ms)，任何异常或超时降级返回原价（degraded=true）

目标 P99 < 20ms，实测比目标低两个量级

基准：1 万条规则、20 行购物车，剪枝后候选 400 条，开发机单次计算均值 ≈0.4ms。

降级不是兜底文案，是一个契约

引擎挂了的后果被限定为「按原价结算」并带上 degraded 标记，主链路不会因为优惠而失败。

规则三级缓存，改完秒级生效

本地快照 → Redis 版本号 → DB 重建（synchronized + double check）。后台 upsert 规则后 bump 版本，全实例刷新——GET 也一并收进了后台前缀，因为规则列表本身就是可反推定价策略的资产。

  1. 1POST /api/seckill/grab → SETNX 防重购标记
  2. 2Lua 分桶原子扣减：hash(userId)%16 定位桶 + 顺序借桶
  3. 3占名额成功即返回 token → 本地消息表 + MQ
  4. 4消费端建单（unique(activity_no, user_id) 兜底）+ sold_stock 原子递增
  5. 5轮询返回 ACCEPTED / SUCCESS:{orderNo} / FAIL:{reason}
  6. 65 分钟未支付由 Job 取消订单并 Lua 回补库存

同步路径只有一次 Redis 调用

DB 写全部异步化；分桶把一个 key 的热点摊到 16 个 key。50 万 QPS 是这一档的设计口径。

预热只有一份口径

启动 Runner 与运维重预热共用 SeckillWarmUpService；非 ONLINE 或已过结束时间的活动拒绝重预热——否则 force 等于给已下线活动重新开闸。

恒等式当验收闸

冒烟断言 分桶余量 + DB 已售 == 总库存，基线从接口读而不写死，对超时取消抖动免疫；超卖、漏扣、回补异常都会破坏它。可连跑 3 轮全绿。

横切边界

管理面写与交易写，是结构分界不是命名约定

改「规则」的写（一次影响所有用户、大多要重算缓存）与记「行为」的写（幂等键 + 削峰） 不是一回事。收口完成的唯一可测证据是：C 端旧写路径直接删掉且不留转发别名，命中就是 40400。留着别名，等于收口只是加了一层前缀。

两套凭证互不相通

C 端 Bearer accessToken 与后台 admin token 各有各的密钥，分别落在根目录的 .consumer-jwt-secret 与 .admin-jwt-secret（已 gitignore；缺失时对应那一片整体拒绝服务）。 空值时 admin 侧启动即失败——宁可不签，也不签一枚谁都能伪造的 token。

审计落表只在一个进程

四个业务进程不连 admin_audit_log，只把 AuditPayload 投进 Redis Stream，由 admin 每 5s drain 落表并 XACK+XDEL。 不用带 TTL 的 list 方案：TTL 淘汰等于静默丢审计。建组从 0 开始， 默认最新位置会让「先投递后建组」那批永远不被读。

乐观锁无处不在

所有改配置的行都带 version，撞了回 41008 已被他人修改， 并附带你看到的与当前的两个数——后台是多人的，运营 A 打开的页面可能已经过时十分钟。 行级冲突不用后写覆盖先写。

界面不复制一份权限

前端角色只用来灰化入口，真正的判定在每个写端点（operator 改阈值仍是 40300）。 三个鉴权码在界面上走三条路：40101 跳登录带 ?next=、 40102 绝不自动重放（那一发可能已经落库）、40100 只清 token。

运行时治理

改阈值不重启，看读数不依赖监控栈

在线配置解决「这个形态该用哪个阈值」，只读大盘解决「此刻它到底在不在跑」。 两者的取数路径都限定在 JDK + Redis + MySQL 之内。

在线配置下发：form 行 > GLOBAL 行 > 出厂值

真值在 admin_config 表，唯一键是 cfg_key + form 两列。 删行 = 恢复出厂，而不是写回原值——否则改了 yml 会被一行陈旧 DB 值永远压住。

admin 写库后按形态各生成一份全量合并快照，各进程每 5s 比对版本号、变了才取。 单键全量而不是每参数一键：多键存在「改了 A 又改 B、读方拿到一新一旧」的半应用窗口。 版本号取 INCR 而不是 MAX+1——并发撞号会让读方停在陈旧快照上。

未声明键在写侧就拒 越界值读侧逐条校验后忽略 快照 JSON 坏了按空应用 落库成功广播失败 → 41009 + 重广播

运维读数：故障时最该能问的三个问题

进程活着吗——读各进程自述键的 TTL，三态判定：有键 = 在跑 / 无键但本档该有 = 没在跑 / 本档压根没这个进程 = 不适用（不参与判活）。

异步堵了多少——local_message 的 PENDING+SENT 跨库求和 + Stream 的 XLEN/XPENDING；跨库靠 information_schema 发现。

缓存和账对不对——gauge 的判定长在 owning 模块里，同一段代码既是修的手也是查的眼，才不会「修完还报不符」。

target 是启动期校验的正面白名单 Redirect.NEVER · 1s 超时 · >256KB 判失败 ④ 只读，这个面里没有任何写

「FULL 档的队列深度只在 broker 里，客户端读不到。那一行就写 applicable=false、 len=-1 加一句说明，而不是 0。把『读不到』画成 0， 就是让大盘在最该说话的时候说『一切正常』。」

诚实的边界

  • LITE 不是洪峰档。入口实测 ~90–100 msg/s（每单 4 个 autocommit × fsync），再往上就是升 FULL 的场景，而不是继续调 LITE 的参数。
  • 判活读数有一处已知缺陷。无可改参数的进程不写自述键，FULL 容器档会把真在跑的 activity / coupon / admin 报成 false（已知 #82）。
  • 一处泄漏待办未修。admin-drain 消费组每次进程启动注册一个消费者条目、从不清理，实测累积 48 个：投递正确、不影响 pending，但 Redis 元数据无界增长。
  • 单库默认共享。跨模块 join 在两个形态里都不会被 DB 拦住，隔离只能靠约定；拆六库就不再有「原地来回切」这个前提。
  • 业务端口不对外收口。FULL 进程形态 808x 绑 *，四个 C 端交易路径本来就不校验 token（鉴权在网关），所以任何形态都不该把业务服务端口暴露到不可信网络。
  • 换数据布局要复位。Redis 分桶键两套布局共用（键名只有活动号），而 sold_stock 各算各的——不重置就冒烟会红在恒等式上，那不是账目错，是两个布局互相不认识。

为什么这些细节值得写进代码注释

仓里的注释承载的是「为什么这么做」：取舍、地雷、机制实测。几个例子——

登录口的 BCrypt 单次 50–100ms 花在 CPU 上，所以后台路由限流（默认 50/s）之外还要一条每 IP 撞库限速（10 次/分钟，含成功尝试），两回事。

口令校验在账号不存在时也跑一次 dummy hash，否则登录口就是一个掐表式用户名枚举接口。

灰度真值故意留在 activity.gray_percent 直接回源 DB，不走 Redis 通知：「Redis 被清空 → 曾设 5% 的活动意外全量」这个后果不该存在。

Lettuce 在 macOS 缺可选原生 DNS 库，网关启动固定打一条 ERROR——不为它往交付物里加平台特定依赖，那会污染 Linux 部署。
